# Multi-Level Maze: Build a Scratch Maze Game

Plan and build a two-level maze game over five lessons. Reuse the Year 5
movement and wall-collision pattern, then add a second route, collectibles,
a patrol hazard, lives, and a clear ending.

You have already used variables and selection in your quiz. This project
reuses those ideas and develops them through a larger game that you plan,
build, test, and explain.

## What you will practise

- planning two connected maze levels with clear starts and exits;
- using keyboard controls, coordinates, and wall sensing;
- tuning movement so it is smooth and fits narrow passages;
- using score and lives variables to track progress;
- using messages and a custom block to manage level changes and endings;
- testing, debugging, and improving a complete game.

## The five lessons

1. [Plan two maze levels](./L01-Plan-and-Prototype)
2. [Tune movement and stop at walls](./L02-Player-Movement)
3. [Add collectibles and a bonus key](./L03-Interaction-and-Score)
4. [Add a patrol hazard and lives](./L04-Challenge-and-Collision)

## Your required game

Your finished project must have:

1. **Two different maze backdrops** connected as Level 1 and Level 2.
2. Four-way movement that cannot pass through the walls.
3. At least three standard collectibles worth one point each and one bonus
   key worth five points.
4. A patrol hazard that removes one life per collision; the player starts
   with three lives.
5. A reusable `check game state` custom block.
6. A Level 1 exit that leads to Level 2, and a Level 2 exit that wins only
   when the score target is met.
7. A clear win and game-over screen.

Build and test one feature at a time. Keep both mazes small enough to finish
in the available lesson time.

## Project log and evidence

At the end of each lesson, record:

1. **I added:** the feature you built today.
2. **I tested:** what you tried and what you expected.
3. **The result:** what happened, and one next step.

Save the Scratch project using your teacher's instructions after every
lesson. Keep the same project so that each lesson builds on the last. If
uploading is difficult, keep the evidence in your computing book and be
ready to demonstrate your game in class.

In Lesson 5, use your test results to make one improvement and prepare to
show how one of your scripts works.
